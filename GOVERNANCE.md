# Governance

Open Quality is currently in an experimental, founder-led phase. This lightweight governance model is intended to make decisions transparent while the initial community forms.

## Roles

- **Maintainers** review changes, manage releases, and protect specification coherence.
- **Contributors** propose and implement changes.
- **Adopters** provide implementation and domain feedback, including cases the specification cannot represent.

## Decision process

Editorial changes may be accepted through normal review. Material semantic changes use a public proposal process:

1. proposal and motivation;
2. public review period;
3. revision based on feedback;
4. recorded maintainer decision;
5. specification, schema, examples, and changelog updated together.

Decisions should prefer demonstrated interoperability over speculative completeness. Lack of consensus is a reason to keep a feature experimental or outside the core.

## Releases

Maintainers publish tagged specification releases. A release must identify its stability, compatible schema location, changes, and known limitations.

## Future governance

Before a stable `1.0.0`, the project should define maintainer nomination, voting, conflict resolution, security reporting, and trademark policies with broader community participation.
