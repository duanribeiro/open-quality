# Security policy

## Supported versions

Security fixes are considered for the latest released version and the current
`main` branch while the project is pre-1.0.

## Reporting a vulnerability

Do not report security vulnerabilities in a public issue. Use GitHub's private
vulnerability-reporting channel for this repository. Include a description of
the impact, reproduction steps, affected version or commit, and any suggested
mitigation. Do not include secrets in the report.

Maintainers will acknowledge a report within seven days and will work with the
reporter on validation, remediation, and coordinated disclosure.

## Scope

Reports may include vulnerabilities in the CLI, schemas, project automation,
and published examples. Specification design feedback that is not a security
vulnerability belongs in an issue or public proposal.
